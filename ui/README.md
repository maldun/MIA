# MIA UI (Godot)

Work in progress, see `REQUIREMENTS.md`. Status: phases 1-4 done (phase list in REQUIREMENTS.md; next: 5 = MIA integration).

Next: the chat page of MIA is to be modernized, see `REQUIREMENTS_CHAT.md` (phases C1-C5).

## Tools (Fedora, Flatpak)

- Blender 5.0 and Godot 4.6.1 as Flatpaks (`org.blender.Blender`, `org.godotengine.Godot`).
- VRM Add-on for Blender 4.10.2 (one time):
  `flatpak run --filesystem=<dir with the zip> org.blender.Blender -b --command extension install-file -r user_default --enable add-on-vrm-v4.10.2.zip`
  (zip from extensions.blender.org, sha256 `228e622d158fbbf070b1b49547708f360a223873f00fa81a42170794492e6db9`).
  The `unregister_class` errors printed at exit are harmless.
- `godot-vrm` (V-Sekai, commit `e15199f`, with the bundled MToon shader) is vendored in `godot/addons/`.

## Phase 1: inspect

`ui/docs/asset_inventory.md` is generated by `tools/inspect_blend.py` (command in the script header).

## Phase 2: export

`tools/export_character.sh path/to/mia.blend` exports VRM 1.0 to `godot/assets/mia.vrm` (git-ignored, 18 MB),
lets Godot import it and checks that every shape key exists and can be driven (`godot/tools/verify_shapekeys.gd`).
Godot lists 57 blend shapes: the 58 Blender keys minus the `Basis` reference key.

`godot/tools/screenshot.gd` renders the character once to a PNG (needs a display).

## Phase 3: web render

- Export templates (one time): download `Godot_v4.6.1-stable_export_templates.tpz` from the godot-builds release,
  verify it against `SHA512-SUMS.txt`, and put `web_nothreads_release.zip`, `web_nothreads_debug.zip` and `version.txt`
  from its `templates/` folder into `~/.var/app/org.godotengine.Godot/data/godot/export_templates/4.6.1.stable/`.
- `tools/export_character.sh` shrinks textures to max 1024 px (`MAX_TEX=0` keeps the originals); the VRM is then 12 MB.
- `tools/build_web.sh` writes the single-threaded web build to `godot/build/web` (no COOP/COEP headers needed).
- `python tools/serve_web.py [port]` serves it (default 8060) with the right MIME types.
- Size: .wasm 36 MB + .pck 11 MB raw; about 20 MB gzipped (the simple server does not gzip).
- Scene: `godot/main.gd` (waist-up camera, arms-down pose, soft light; mouse drag/wheel and touch drag/pinch).
- `godot/tools/screenshot.gd` renders the scene to a PNG; headless Chromium with SwiftShader also works for web checks.

## Phase 4: expressions

- `godot/expression_engine.gd` (`ExpressionEngine`): the central API. `play(name, duration)` / `apply_preset(dict, duration)`
  blend smoothly (default 0.25 s, easing `smooth|linear|sine|cubic`), keys not in the new preset go back to 0,
  automatic blinking (2.5-6 s apart, suppressed while the eyes are closed), subtle idle motion (breathing, head sway).
  `validate()` rejects unknown shape keys / bone params, clamps values and logs every correction.
- Presets: `godot/presets/library.json`, `{"presets": [ {name, description, weights, bones, tags, source} ]}`.
  The 14 required ones: greet, no, annoyed, talk, yes, idle (from `expressions.json`) and neutral, happy, sad, angry,
  surprised, embarrassed, smug, thinking. Bone params (degrees): head_pitch (+ down), head_yaw (+ viewer's right),
  head_roll, eye_pitch, eye_yaw.
- Tests: `godot --headless --path ui/godot --script res://tools/test_expressions.gd` (checks validation, blending, blinking, idle).
- Review: `godot/tools/contact_sheet.gd` + `tools/montage.py` render all presets into one image;
  the web page has a collapsible button bar to play them (temporary, replaced by the editor in phase 6).

### Gestures, camera and the eye fix (after phase 4)

- `godot/gesture_engine.gd` + `presets/gestures.json`: relaxed arms by default, 12 gestures; a preset can start one (`"gesture"`).
  Preview all poses with `godot/tools/gesture_sheet.gd`.
- Default camera shows the whole figure; the menu (collapsed at start) has camera views body/bust/face, all expressions and gestures.
- Fixed: in Godot 4 a bone pose is the *absolute* local transform, not an offset from rest. The first engine version set the
  eye bones to "identity", which rotated them 90 degrees and hid the irises. The same mistake is fixed in the arm pose.
  `godot/tools/eye_closeup.gd` renders an eye close-up for checking this.

### Gesture rework (hands, palms, speaking)

- `gesture_engine.gd` now poses arms from directions + palm directions and curls the fingers (poses: relaxed, open, fist, point).
  `explain` (palm-up open hand) replaced pointing for `talk`; `point` (index finger out) stays available.
- A gesture started from the menu also shows its face (`"expression"` in `gestures.json`); presets that start a gesture do not loop back.
- `talk` has `"speaking": true`: the mouth moves through vowels (`Fcl_MTH_A/I/U/E/O`).
- Menu: the active expression/gesture is highlighted, "stop gesture" is the first button of the gesture row.
- Taps on a phone: `emulate_mouse_from_touch` is on again (buttons need it); the camera code ignores the emulated mouse events.
- Tests: `tools/test_expressions.gd` (headless) and `tools/test_menu.gd` (presses the menu buttons; run it with a window to include real clicks).

## Phase 5: MIA integration

- `expressor.py`: `PresetExpressor` replaces `VideoExpressor`; `express(key)` sends the preset name to the page, unknown keys are logged and ignored.
  `VoiceExpressor` skips expressions without a voice clip.
- `web_app.py`: `express_and_reload()` emits the socket.io event `expression` ({"name": preset}) and plays the voice clip;
  `/character/` serves the web export (folder `character_dir`, default `ui/godot/build/web`, with the `.wasm` MIME type);
  a page that loaded the character announces `character_ready` and gets the current expression (idle after the start).
- `templates/index.html`: an iframe with the character replaces the `<video>`; the page forwards `expression` events to it (`postMessage`)
  and tells it when the voice is playing (`speaking`).
- `godot/host_bridge.gd` receives these messages; the dev menu is hidden inside the iframe (add `?menu` to `/character/` to see it).
- `emotion_map.json` has six new emotions (sad, angry, surprised, embarrassed, smug, thinking), `expressions.json` six new expressions without voice clip yet
  (generate with `speak.py --generate`, note: it regenerates all clips).
- Tests: `python tests/test_character_integration.py` (MIA virtualenv), `godot/tools/test_bridge.gd` (headless),
  `python ui/tools/browser_check.py <url> <out.png>` opens a page in headless Chromium and reports the console.

### HTTPS for other devices

Godot's web export (audio worklet, WebGL) needs a secure context. `http://localhost` is one, `http://<lan address>` is not:
other computers and phones get a message that HTTPS is needed. `tools/https_proxy.sh <https port> <target host:port>`
runs a TLS proxy (openssl + socat, self-signed certificate in `ui/certs`):

- `ui/tools/https_proxy.sh 8586 <lan address>:8585` for MIA's page (and `"https_port":8586` in `setup_cfg.json`),
- `ui/tools/https_proxy.sh 8443 127.0.0.1:8060` for the character test server (`tools/serve_web.py`).

The chat page connects to the socket of the address it was loaded from, so the same page works on localhost, in the LAN and over HTTPS.
`python ui/tools/browser_check.py https://<address>:8586/ out.png --insecure` checks a page in headless Chromium.

### Emotions (decisions after phase 5)

- `happy` uses the `happy` preset (broad smile, cheer gesture); `neutral` uses the calm `neutral` preset (no gesture,
  no "Listen!" clip). Both expressions have no voice clip yet; the mouth still moves while MIA's voice plays.
  `MIA`, `agree`, `disagree`, `annoyed` keep their expressions (greet, yes, no, annoyed); `talk` stays available but is no emotion anymore.

### Custom background

- Pictures (png, jpg, webp) in the `backgrounds` folder of MIA (`"background_dir"` in `setup_cfg.json`) are shown behind the character;
  the first one at the start, or `"background_image"`. See `backgrounds/README.md`.
- `web_app.py` serves them: `GET /character-backgrounds.json` ({"files": [...], "default": ...}) and `GET /character-backgrounds/<name>`
  (only pictures of that folder). The character (`godot/background_manager.gd`) loads them from the server it came from and
  draws the picture on canvas layer -1, scaled to cover the view; on the desktop it reads `<repository>/backgrounds` directly.
- The page can switch it with `{"type": "background", "name": "room.jpg"}` ("" = plain colour); the menu (`/character/?menu`) has a Background row.
- Tests: `godot/tools/test_background.gd` (headless) and the background tests in `tests/test_character_integration.py`.

### HTTPS starts with MIA

`python -m MIA` listens on all addresses (`"host"` in `setup_cfg.json` restricts that) and starts `tools/https_proxy.sh` when `"https_port"` is set
(code: `tls_proxy.py`); missing `socat`/`openssl` are logged and MIA runs without the proxy. Tests: `TlsProxyTest` in `tests/test_character_integration.py`
(including a real HTTPS request to localhost through the proxy).

## Phase 6: expression editor and preset API

- **Backend:** the preset API is part of MIA's Flask app (`presets_api.py`, storage in `preset_store.py`), not a second FastAPI server:
  the page, the character and the presets come from one server with one set of access rules (HTTPS proxy, allowed origins, token).
  One json file per preset in `presets_dir` (default `data/presets`, git-ignored), filled from `godot/presets/library.json` on first use.
  REST: `GET /api/presets` (all + version + `token_required` + protected names), `GET /api/presets/version`, `GET /api/presets/<name>`,
  `POST /api/presets`, `PUT /api/presets/<name>` (a different name in the body renames), `DELETE /api/presets/<name>` (409 for presets
  MIA's emotions use, `?force=1` overrides), `GET /api/shape-keys`, `GET /api/gestures`.
  Values are corrected like in the character (unknown shape keys, bones and gestures removed, values clamped) and reported as `corrections`.
- **Safety:** writing needs `Content-Type: application/json` (no cross-site form posts), a known origin if the browser sends one
  (the page's own address is always fine), and the header `X-MIA-Token`. The token is created on the first start (`data/editor_token.txt`, mode 600, not in version control, printed at start); `editor_token` in the configuration overrides it, `""` switches it off. Desktop clients (tests) read it from `MIA_TOKEN` or the file `MIA_TOKEN_FILE`. Names are 1-40 letters, digits, `-`, `_`
  (no paths), files are written atomically, bodies over 64 KB are refused.
- **Character:** `godot/preset_api.gd` (client, polls the version every 10 s so other devices' changes show up; offline it keeps the
  bundled presets), `godot/expression_editor.gd` (the panel: right side on wide screens, bottom sheet on phones, big slider handles,
  solid background), `godot/presets/shape_keys.json` (categories and descriptions of the 57 shape keys, also used for validation and,
  later, for the LLM prompt). `?editor` opens the editor at start, the dev menu has an "Expression editor" button.
  The stretch aspect is `expand` now: the canvas fills any window (no black bars next to the character).
- **Tests:** `python tests/test_presets_api.py` (23 tests: storage, rules, API, token, origin),
  `godot --headless ... --script res://tools/test_editor.gd` (43 checks with an in-memory server),
  `MIA_URL=http://127.0.0.1:8685 godot ... --script res://tools/test_editor_live.gd` (real HTTP against a running MIA app and a second client
  as "another device"), `tools/editor_shot.gd` renders the editor to a PNG (wide and phone shapes).

- **Kept for now:** the old socket events (`message`, `answer`, `audio_reload`, `audio_ended`, `expression`, `character_ready`); `chat-lite.js` shows

## Chat backend, phase C2

The server now describes the conversation as **messages** (`chat_service.py`, `chat_log.py`, `chat_api.py`, `moods.py`).
`chat_send` is answered immediately; the exchange runs in a background task (one at a time, one more may wait), so the socket
handler never blocks. The old events (`message`, `answer`, `audio_reload`, ...) still work for the page of C1 and are removed in C3.

| Direction | Event | Payload |
|---|---|---|
| page -> server | `chat_send` | `{id, text}`, acknowledgement `{ok, message, queued, command}` or `{ok: false, error}` |
| page -> server | `chat_stop` | acknowledgement `{stopped}`; the text received so far stays, the message is marked `stopped` |
| server -> all | `chat_message` | a complete message: yours, system notes (commands), automatic MIA messages (`auto: true`, e.g. the hourly time check) |
| server -> all | `chat_start` / `chat_delta` / `chat_done` | MIA's answer: start, cumulative text (at most about 20 per second), final `{id, text, emotion, status}` |
| server -> all | `chat_status` | `{busy, activity, model, profile, queue, mood: {emotion, emoji, text, since, activity}}`, also sent on connect |
| server -> all | `chat_error` | `{id?, message}` |

REST: `GET /api/chat/history?before=<id>&limit=50`, `GET /api/chat/status`, `GET /api/chat/commands`,
`POST /api/chat/clear {"scope": "log"}` (header `X-MIA-Token`, the editor token unless `chat_token` is set).

- **Mood line:** `moods.json` (edit it; read again when it changes) holds first person phrases per emotion keyword and per activity
  (thinking, dreaming, offline ...). The phrase is chosen on the server, never the same twice in a row, and sent to every device;
  a mood returns to "Ready when you are." after `mood_hold_minutes`.
- **Not in the chat log:** calibration, the hourly prompt to the model, summaries and penalties (the reminder to start with an emotion).
- **Stop:** `Communicator.exchange(should_stop=...)` closes the stream to Ollama and keeps the received text in MIA's history.
- **Tests:** `python tests/test_chat_backend.py` (33 tests: log, mood, service with a fake model, stop, queue, errors, rate limit, REST, two clients).

## Chat page, phase C3 (the real conversation)

The page now uses the `chat_*` events of C2 (the C1 bubbles and the old `answer` event are not used any more).

- **Code:** `chat-model.js` (pure: ordering, grouping, times, links, command filter; tested with node), `chat.js` (history, live messages, streaming
  batched per animation frame, sending with retry, paging, autoscroll, unread count), `mood.js` (live mood line), `palette.js` (slash commands,
  confirmation dialog), `composer.js` (stop button, queue hint, draft, up-arrow recall, length counter), styles in `messages.css`.
- **Messages:** bubbles for you (right, links clickable, shown as typed) and MIA (left, markdown, sanitized), sender line with the emotion badge and an
  "automatic" tag for her own messages, relative times (full date as tooltip), day separators, copy button, state text (sending, waiting, stopped, error,
  retry when it could not be sent). Several devices see the same conversation; your own message is upgraded in place when the server confirms it.
- **History:** the last 50 messages on load (`/api/chat/history`), older ones while scrolling up (or the button), at most about 300 rows in the page.
  After a lost connection the page reloads the latest messages. "New messages (n)" appears when you scrolled up.
- **Composer:** Enter sends (Shift+Enter newline; on touch screens the send button sends), while MIA answers a stop button appears and one more message
  waits in the queue, `/` opens the command list (dangerous commands ask first), the field is disabled for sending while offline.
- **Mood line:** shows exactly what the server says (`chat_status.mood`), crossfades, adds a sound icon while MIA speaks, and tells screen readers at
  most every 30 seconds. The header chip shows the model (light or full).
- **Tests:** `node --test "tests/js/*.test.mjs"` (16), and the browser check `ui/tools/chat_stub_server.py` + `ui/tools/chat_e2e.js` (history, paging,
  streaming, mood changes, palette, stop, error; see the header of the stub server).
- **Still old:** the server still emits `answer` and writes `answer.html` for the old page, and still handles the old `message` event; both go in C5.
