# FB-03: Re-specify how workflow pipelines are built

- Type: Change of design (owner's direction for the next iteration)
- Observation: building and changing a workflow pipeline today goes through several forms and version chains that do not line up:
  - The runnable pipelines are JSON trees in `library/pipelines/` (`library.py`), separate from the workflow documents of IF-203, which hold graphs without executable content; the two are tied by "reference + sync" (D-112, `run_workflow.sync_skills`).
  - Pipelines pin node versions (`"use": "tool.web_search@1"`). A changed node needs a new node version, and every pipeline that should use it needs a new version as well, with a dev eval run (agent-app rules). Example: the Verify finding F12 of N-2.4.1 gave `tool.web_search@2`, but the 7 versions of the 4 research pipelines still use `@1`.
  - Experiments sit side by side as versions of the same pipelines (`research.baseline` 1, `research.decompose` 1–2, `research.escalate` 1–3, `research.typed` 1, all `draft`); which one runs is set by the skill (`research.escalate@1`) or by an eval variant.
  - Not every workflow is a pipeline: the review is Python control flow (`review_chat.run_review`), so it cannot run through the same runner (REQ-RUN-013 AC-9; task T-08, A-35).
- Evidence: owner's remark of 2026-10-31 (chat, after the question "why are there 6 research pipelines?"); `library/pipelines/research.*`, `library/nodes/tool.web_search/`, N-2.4.1 `verification-report.md` (F2, F12), D-112, D-126
- Cause (if known): the pipeline format grew from the research experiments (13b, ST4, ST10) before workflows became library documents (IF-203) and before the graph app; versions are immutable once runs are recorded, which is right for evals but multiplies versions.

- Proposed change (owner, 2026-10-31): re-specify how workflow pipelines are built: one form for what a workflow is and how it runs, how nodes and their versions are referenced, how strategies and experiments are kept apart from what runs, and how a change moves from a node to the pipelines that use it. To be explored together with FB-02 (networkx graphs whose nodes are operations and data objects), which changes the same form.
