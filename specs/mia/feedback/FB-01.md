# FB-01: A skills panel beside the chat; the chat keeps only the questions and a summary of the result

- Type: Usability
- Observation: in the owner's live test of `/review` the chat became confusing: the status card, the progress and the long result of a skill all sit in the one chat window between the conversation.
- Evidence: owner's report of the live test, 2026-10-30 (chat with the agent; no recording)
- Cause (if known): REQ-WFM-036 and REQ-CLV-023 put the status card and the full result into the chat (A-23, A-24, A-27); there is no other place for a running skill.
- Validated version: master `058588d` (compose stack, owner's hand test; no release tag yet, no deployment record)
- Source: exploratory
- Affects:
  - Requirements: REQ-CLV-023 (status card in the chat -> in the skills panel), REQ-CLV-024 (files list, link target), REQ-WFM-031 (task monitor: where the card is shown), REQ-WFM-036 (result at the end of the chat -> a short summary with a link), REQ-WFM-038 (report as a record: the link target), REQ-FE-014 (parent), REQ-CHA-008/-014 (persona, repair of what is spoken), speech of the chat (N-2.5); new: the skills panel (N-1.1), questions and summary spoken by the voice, questions and summary in the history the chat model sees
  - SysML parts: WebFrontEnd (N-1.1 Chat and login views), TaskRuntime (N-2.3), ChatAgent (N-2.2), Voice synthesis (N-2.5)
  - Interfaces: IF-101 (events `task_status`, the result message; possibly a flag that marks a message as skill output), IF-201 (chat turn: the history the model sees)
  - Tests: TC-CLV-023, TC-CLV-024, TC-WFM-031, TC-WFM-036, the IF-101 contract tests of the review (TC-IF-101-24, -25), `tests/js` of the card
- Proposed change (owner's answers 2026-10-30):
  1. A **Skills panel beside the chat** on the same page (a tab like Files, a tab on the phone): status cards, progress, pause / resume / stop, the full result and the report link of every running and finished skill.
  2. **In the chat only:** the questions a skill asks while it runs, and when it ends a **short summary of the result with a link** to the full result (panel or Files). A failure is a short message with the reason (keeps REQ-WFM-036's rule) and a link.
  3. **MIA speaks** the questions and the summary (voice, like an answer; repaired text as for answers).
  4. **MIA knows** the questions, the user's answers and the summary: they are part of the chat history the model sees, so the user can talk about the review afterwards.
