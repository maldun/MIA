# FB-02: Workflow and context graphs as networkx graphs of objects; the graph app with vis.js

- Type: Change of design (owner's direction for the next iteration)
- Observation: workflows are stored as plain graph documents without executable content (IF-203, D-112 "reference + sync"); the runnable pipelines are separate JSON trees in `library.py`, and `graph_rules.py` checks plain dicts. The graph app (N-5 T-01) draws plain SVG without moving nodes.
- Evidence: owner's answers of 2026-10-31 (chat; D-121, D-122)
- Cause (if known): the HLS of 2026-10-24 asked for plain, storable graph documents and a vendored graph library for the view (FR-7, FR-22); no graph library was chosen.
- Validated version: – (direction, not a finding of a test)
- Source: owner
- Affects:
  - Requirements: FR-7 (graph rules), FR-22 / REQ-GA-009 (graph app, vendored library), REQ-RUN-012, REQ-RUN-013 (how the runner reads a workflow), the requirements of N-3.2 (workflows and context graphs)
  - SysML parts: TaskRuntime (N-2.4.1), Workflow management (N-2.3), Graph tables (N-3.2), Graph app (N-5)
  - Interfaces: IF-203 (workflow library), IF-301 (graph tables), IF-104 (graph API)
  - Tests: the graph rule tests (`tests/helpers/mocks/graph_rules.py`, `graph_rules.py`), the contract suites of IF-104, IF-203, IF-301, the N-5 tests
- Proposed change (owner, 2026-10-31):
  1. In Python, workflow and context graphs are `networkx` graphs. Nodes are Python objects: a process node can be an operation (a program or function that does the work), a data node a complex object with its own logic. A workflow is then stored together with its set of operations, not only as plain data.
  2. The graph app draws with vis.js (vis-network) or a related library that lets the user drag and move nodes: interactive editing of the graph is part of the experience.
- Open for Explore: how operations are stored and versioned when they are code (X3: skills and pipelines are read-only for models; the trust boundary of code in a graph); the storage form of a graph of objects (IF-203, IF-301); what replaces D-112; the two new dependencies (`networkx`, `vis-network`) and their licences; whether the plain-dict form stays as the exchange format.
