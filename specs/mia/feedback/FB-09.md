# FB-09: a skill run gives feedback too often and speaks its text twice

- Type: Defect and usability (proposed)
- Observation: the owner, 2026-11-16: "The agent (MIA) gives feedback too often and speak out the text twice when a skill is called". No skill named, no recording
- Evidence: owner's remark in the chat of 2026-11-16; not yet reproduced by me. Leads from the code of master (e3eeaa8), not proven:
  - Twice: `/lookup` and `/review` get `speak=services.speaker(task)` (`extensions/lookup/entry.py:13`, `extensions/review/entry.py:28`). `research_chat.run_research` speaks `spoken_text(result.answer)` itself (about line 135). At the end of the run the chat service also words a `done` turn and sends it to speech (`chat_service._do_chat` -> `_turn_text`, `_voice(message_id, summary)`; REQ-CHA-045, "every added message is spoken once"). So one run has two spoken texts (the answer and the summary of it), when the run is a skill with a voice and the digest step is on
  - Too often: every declared phase is its own message and goes to speech (`skill_turn(..., "phase", ...)`, `on_phase` of `SkillRunObserver`), as does every question and the end message, so a run with phases talks at every step. By REQ-CHA-045 this is as specified, so it may be the specification that is too chatty
  - Not checked: whether the graph path of the five converted skills (`core._run_converted`, `on_event` with `run_start`, tool events, `run_end`) adds events that reach `pipeline_event` and the status block more often than the old runner. The old path and the graph path should be compared in a run before it is blamed
- Cause: open (leads above)
- Validated version: master at e3eeaa8 (current checkout), not a release
- Source: owner, 2026-11-16
- Affects:
  - Requirements: REQ-CHA-045 (every added message is spoken once), REQ-CHA-040..047 (skill turns), `workflow_voice.speaker_for` (one voice rule for all tasks, owner 2026-10-29). Possibly a new requirement: a run speaks its result once (answer or summary, not both) and a limit for spoken phase messages
  - Parts: `chat_service.py` (`_voice`, `skill_turn`, `_do_chat`), `research_chat.run_research` (`speak`), `extensions/lookup`, `extensions/review`
  - Tests (proposed, red first): a `/lookup` run with a voice records the sentences handed to the voice route; a sentence of the answer and the digest summary together must not be both spoken; a run with three phases speaks at most what the rule allows
- Proposed change (decided, see above): decide with the owner which of the two spoken texts stays (the summary of the digest step in persona, or the answer) and whether phase messages are shown but not spoken. Then amend REQ-CHA-045 (protected, an amendment) and test it
- Priority: Should (proposed)
- Raised by: Stefan Reiterer (owner), 2026-11-16
- Status: Decided by the owner 2026-11-16, amendment to draft
- Decision / reason: owner 2026-11-16: (1) of the two spoken texts the persona summary (the digest `done` message) stays; the answer of the skill itself is not spoken a second time. (2) phase messages are shown but not spoken, because they are not in character. Addition the same day: a status noted once is not repeated; phase messages stay in the Skill run view and out of the chat (they clutter it); only messages that need interaction belong in the chat; the end message of a run (persona summary with the link) stays in the chat and is spoken (owner, later the same day)
