# FB-08: sources should be clickable hyperlinks, automatically

- Type: Usability (proposed)
- Observation: the owner, looking at a window of the app: "It looks good, but the sources should be able to automatically be clickable hyperlinks". The sources are shown, but not as links. The owner wrote "kill window"; no window of that name exists in the UI texts, so the owner confirmed on 2026-11-16: the skill window (Skill run view), part Full run, when the `lookup` skill ran; the sources listed there are plain text
- Evidence: owner's remark in the chat of 2026-11-16; no screenshot
- Cause: `templates/static/chat/skill-run.js`, `drawFull`: result, answers and material are set as text nodes (`textContent`) on purpose, so no URL in them can be a link. This is what REQ-CLV-043 demands ("plain text that starts no action"). The chat bubbles are not affected: they go through `markdown.js` (marked + DOMPurify), where links already open with target=_blank and rel=noopener noreferrer
- Validated version: master at 5825d1b (current checkout), not a release
- Source: owner, 2026-11-16
- Affects:
  - Requirements: REQ-CLV-043 (Texts of a run are text; a link starts an action, so it conflicts with it as written), parent REQ-FE-032, AC-39, TC-CLV-043, TR-PANEL-005. A change of REQ-CLV-043 (amendment) is needed first
  - Parts: front end, `skill-run.js` (`drawFull`, the material list `srv-material`)
  - Tests: none yet. The protected `tests/acceptance/test_skill_run_view_browser.py` (TC-CLV-043) requires hrefs only `/api/files/<encoded>`, and its hostile list holds `<link ... href="http://evil.example/x.css">` (also in `material`): a linkifying view would fail it. New unit tests (tests/js/) wait for the amendment
- Proposed change: render a source that has a URL as a link (opens in a new tab, rel noopener), also in text the model wrote; a source without a URL stays text. Untrusted text rule: only http and https addresses become links, never javascript: or data: (trust boundary, a red-team case for the renderer)
- Priority: Should (proposed)
- Raised by: Stefan Reiterer (owner), 2026-11-16
- Status: Blocked, waiting for an amendment of REQ-CLV-043 and TC-CLV-043 (stop condition: the fix changes a requirement and a protected test)
