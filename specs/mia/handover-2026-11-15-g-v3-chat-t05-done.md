## Pitfalls met in this stretch (keep)
- The owner's `deploy/.env` sets `OLLAMA_URL`, so `deploy/up.sh` starts the MIA stack but no Ollama; start the container `ollama` by hand.
- `tools/eval.py run` needs `--pin MP-light`; a run writes `data/eval/` (git-ignored). Repeats, seeds, thresholds and decision rules are fixed; a failing criterion is re-run once, never more. The runs of T-05 are feedback.
- A merge that auto-resolves can still be wrong: after `goal/v3.chat` took the renamed D-numbers by cherry-pick, old and renamed rows of the review log stood side by side (found and removed at the merge `48c143e`).
- The permission classifier blocks `install.py` even as a dry run; check a payload with `git apply --check` instead.
- The marks file of the labelling form is always `~/Downloads/digest-marks.json` and is overwritten by the next download: apply it before labelling the next form.
- Background commands: put the long command itself in the background (`run_in_background`), not a `( ... ) &` subshell, or the notification fires when the launcher exits.
- A tool that prints the commit it made is not proof: check `git log -1` before relying on it.
