## Pitfalls met (keep)
- **Never touch the checkout while a full suite runs**: `test_checkout_untouched` flags any file written or committed during the run. Start long runs with `run_in_background` (a `( ... ) &` subshell gives no notification and leaves idle `bash -c` wrappers); give the suite a timeout of at least 1500 s (it takes about 8.5 minutes; a 590 s limit killed it once, exit 144).
- **Labels are read when a run is scored.** A holdout run is made before its outputs are labelled, so the stored run says `open`; `eval_decide` then reports 0 cases (not a verdict). Use `rescore_digest_run.py` (it must update both copies of the score, `output.score` and the top-level `score`). A run file is evidence: never edit it.
- **The marks file of the labelling form is always `~/Downloads/digest-marks.json` and is overwritten by the next download.** Apply it right away; check its time and size before applying; the form does not show what is already labelled (use `make_digest_label_form.py --labels`). Applying an old marks file to the holdout suite writes wrong holdout labels (happened once, deleted).
- **An agent never runs or opens a holdout, its cases, outputs or labels**, also not by a `wc -l` or `ls` that names them: the classifier blocks it. Ask the owner to run a command and paste the output.
- A `: ` inside the plain text of a YAML basis broke `plausibility.yaml` once (found by a reviewer): check a protected-file patch with `yaml.safe_load` and `req_plausibility.py` on the final file, not an earlier version.
- `sed` on `deferred.md` is blocked by a deny rule: read it with the Read tool; changes go as a patch.
- A reviewer subagent cannot write files (the environment refuses): it returns the report as text and the implementing session saves it. Do not ask it again to write.
- Narrow adversarial reviews of the same code keep finding the next edge case. Put the guarantee at the end of the function (escape, fail closed, never raise) and keep the patterns as the nicer path; Python's `int()` limit (4300 digits) and a lower-cased copy with other indexes (`İ`) were two of the traps.
- Suspected, not verified: `trace_check` seems to look only at the first requirement ID of a TD's `Requirement:` line (TD-85 names REQ-CHA-056, 064 and 066, only 056 was reported).
