Code never derives one from the other. A quote that is not in the source downgrades a judgement to `maybe` (`unverified_quote`); a section whose quote is not in its text does not count for the grade.

## Owner decisions of today (do not re-ask)

New keywords only after approval (N = 3, a starting value). Summary stage as a convenience for a person to check, not perfect. ## Config (owner's `setup_cfg.json`, not in git)
`"review_budget": {"seconds": 180}` (default 60). The other limits stay: screen 40, read 10, calls 150, tokens 400000, api_requests 80, checkpoint_every 10. MIA says each question of `/review` and a short result aloud through `speak_answer` (the markdown report is never read). The voice of the tasks beside the chat has ONE rule, `workflow_voice.speaker_for(cfg, task, speak)`: general switch `"workflow_speak"` (default true) and optional `"workflow_speak_tasks": {"review": false}` over it; every new workflow that speaks must ask it (today `/lookup` and `/review`); read at start, so a change needs a restart; `review_answer_seconds` (default 1800) is the time the review waits for a reply (no reply = "no"). Each used-up limit that gets a "yes" grows by its first size. Fewer questions would need a design change (an `auto` mode) and so an amendment of REQ-WFM-019.
