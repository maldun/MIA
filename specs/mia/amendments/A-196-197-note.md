## A-196: records no graph names are synced like a graph (V-2)

**Why.** Verify (V-2) found that a record of the graph group that no header names was not synced. If it was only on the copy, it stayed there, so the copy did not equal the live store (against REQ-SLY-025), while the lag said "current". If it differed, the whole sync was refused with `conflict`, and the lag still said "current". The owner chose to sync such a record like a graph: aside file, then cut back, removed when only on the copy, and listed by the lag.

**Changed, not protected (in the commit of this amendment's drafts):**
- `requirements.md`: REQ-SLY-024, 026, 027 (new text) and REQ-SLY-025 (new acceptance criterion; the text already asked for every record) are moved to "Changed requirements", each with its approved text `In force:`. Verified by TC-SLY-040 too. Terms: "record no graph names" is new; "lag" and "aside folder" say how such a record is keyed (`<table>|<record ID>`) and how its aside file is named. Group SY marks the four as changed.
- `test-spec.md`: TC-SLY-040 (table row, scenario, coverage rows of lag and sync).

**Changed (protected, installed by the script):**
- `tests/acceptance/test_transfer_sync.py`: TC-SLY-040, live store on files and on the database. TC-SLY-022 to 031 are unchanged.
- `test-requirements.md`: TC-SLY-040 is added to the "Applies to" lines of TR-TRANSFER-001 (exact values), 002 (both backends), 005 (times copied compared exactly) and 007 (throw-away stores only).

**Consequences the owner should see before approving:**
- Every skill is a record no graph names (`skills` is in the graph group, and no header names a skill). A skill the copy lacks is now listed as `skills|<id>` `behind`. One that differs is set aside instead of refusing the whole sync.
- `lag_summary` (REQ-API-064, IF-104 v2 `lag.graphs`) counts the rows of the lag, so a record no graph names counts as one. `since` stays counted from header versions, as D-540 says. REQ-API-064 is not changed; if the owner wants `graphs` to count graphs only, that is one more line of text.
- The sync no longer answers `conflict` for such a record. The unit check `Sync.test_a_differing_record_outside_every_graph_is_a_conflict_before_any_write` is rewritten with the implementation.
- The `sync` command prints its usual line per set-aside item, now also for a record (`  graph_nodes|lonely.g/z: versions [1] set aside in ...`).
