## Pitfalls met in this session
- `podman-compose up --force-recreate` of one service removes its neighbours and a plain `deploy/up.sh db` can fail with "cannot remove container ... as it is running"; apply a changed setting with `deploy/up.sh db restart mia`, restart everything with `down` then `up`, or clear a stuck pod with `podman pod rm -f pod_mia` (volumes stay).
- In the container the working directory is `/opt/mia`, the code is `/opt/mia/MIA`; the container is renamed at every recreate, so use `deploy/up.sh owner` and friends, not `podman exec ... mia_mia_1`.
- A scripted edit that anchors on a text found twice (a header comment and the real block) once replaced the top of `deploy/up.sh`; the tests caught it. Anchor on a unique line and check the count.
- Tests that import the app through the link trick (`MIA.`) must use the classes of the same import (`tests/task_helper.py` takes a prefix).
- A protected-file `cp` is sometimes refused by the harness; the drafts under `specs/mia/contract-drafts/tests/` equal the installed files after an install, so edit the drafts in place.
